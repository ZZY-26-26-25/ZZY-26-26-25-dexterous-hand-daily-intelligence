## 2. 重点解读

### HandUMI Hardware + Software

- **原始链接：** [硬件仓库](https://github.com/robonet-ai/handumi-hw) · [软件仓库](https://github.com/robonet-ai/handumi-sw) · [在线文档](https://robonet-ai.github.io/handumi-sw/)
- **一句话概括：** 一套约 221 美元/双手（不含 VR 头显）的开源穿戴式 UMI，操作者直接用类似平行夹爪的手部接口操作真实物体，原始示教保持机器人无关，之后可映射到不同双臂平行夹爪机器人。
- **硬件是什么：** 设备固定在拇指和食指/中指上，以自然捏合驱动机械开合；主体、相机架、伺服和控制器支架可复用，只需替换末端 tip 适配不同机器人夹爪。当前公开 tip 覆盖 AgileX PiPER、ARX X5、Dream Gripper/TRLC、Trossen WidowX AI 和原始 UMI 夹爪。每只硬件 BOM 约 110 美元，双手约 221 美元，PICO 4 Ultra 或 Meta Quest 3 另购。
- **采集/控制链路：**  
  `XR 控制器 SE(3) + Feetech 编码器开度 + 腕部鱼眼视频 → 同步 robot-agnostic capture → 校准/有效性检查 → retarget → MuJoCo replay → PiPER/OpenArm 等真机`。软件通过统一 `handumi` CLI 提供 `doctor/setup/record/validate/replay/retarget/teleop` 等流程，并将机器人配置、控制器到 TCP 的物理标定及文件 hash 写入数据元信息。
- **自由度与传感：** 每只手不是完整人体关节手套，而是一个 6D 腕部轨迹加 1D 夹爪开度的动作接口；腕部位置由头显世界坐标系和腕部控制器提供，开度由 Feetech 伺服编码器直接测量，视觉由腕部广角 UVC 相机提供。
- **反馈方式：** 操作者直接与真实物体接触，能自然感受阻力、摩擦和物体变化；但系统不电子化记录触觉/力，也没有电机驱动的主动反馈。
- **如果是产品/开源：** 硬件和原创软件采用 Apache-2.0，公开 STL、BOM、装配说明、数据采集、校准、验证、回放和 retarget；原始数据可保持机器人无关，派生数据可转换为 LeRobot-compatible captures。
- **和 DexUMI / DOGlove / UMI-Dex / SynGlove 等已有方案的关系：** 与传统手持 UMI 相比，HandUMI 将接口戴在手上并直接用捏合测量开度，双手操作更自然；与 DOGlove/MANUS 等全手手套相比，它不测完整手指姿态，只服务平行夹爪；与 SynGlove/CDF-Glove 相比，它没有主动反馈；与 DexUMI 多指代理端相比，动作维度低但成本和复现门槛显著更低。
- **对我们搭建灵巧手数据采集平台的启发：** 可作为“无本体采集软件栈”的直接参考，尤其是 `原始数据不绑定机器人 + retarget 派生数据单独版本化`。我们应保存原始人体/代理端数据，派生 PiPER、Franka、灵巧手动作时记录 `target_robot_config_hash`、`controller_tcp_calibration_hash`、`retarget_mode`、`source_episode_id` 和误差统计。
- **风险或不确定性：** 只支持平行夹爪动作，无法表达多指接触与手内操作；XR 绝对位姿受漂移、遮挡和头显生态影响；手指托架按个体 3D 扫描设计，规模化使用需解决尺码与舒适性；机器人无关不等于机器人可执行，仍需在目标机器人上做 IK、碰撞、速度和接触验证。

### Trossen TRumi

- **原始链接：** [产品页](https://www.trossenrobotics.com/trumi) · [数据生成文档](https://docs.trossenrobotics.com/trumi/dataset_generation.html) · [UMI 工作流说明](https://www.trossenrobotics.com/post/what-is-umi-data-collection)
- **一句话概括：** 将原始 UMI 的开源研究概念重构为可购买、可维护、支持长期重复采集的商业手持系统，并把 GoPro、SLAM、标定和数据格式做成标准流水线。
- **硬件是什么：** CNC 金属结构、凸轮驱动触发、双线性导轨和双恒力弹簧；触发拉力约 0.4 lb，末端标识直接嵌入结构，减少贴纸脱落；相机为 GoPro HERO13 Black + Ultra Wide Lens Mod，标称 177° 视场。
- **采集/控制链路：**  
  `mapping video → GoPro IMU 提取 → ORB-SLAM3 建图 → demo 批量定位 → ArUco 检测 → SLAM/tag/开度标定 → dataset plan → MCAP/Zarr`。120 fps 视频通常以 60 fps 运行视觉惯性 SLAM，以保证约 200 Hz IMU 每个 SLAM 帧至少有 3 个采样。
- **自由度与传感：** 每只设备输出端到端 6D 位姿、夹爪开度、相机图像；MCAP还保留原始加速度计和陀螺仪。它不记录完整人手关节，不含电子触觉或指尖力传感器。
- **反馈方式：** 人直接通过工具接触真实物体；恒力弹簧主要改善触发手感和重复性，不是可编程触觉反馈。
- **如果是产品：** 官方标准价为双 TRumi（含两套 GoPro+超广角）2,195.99 美元；不含 GoPro 的双设备为 949.95 美元。2026-07-27 官方促销信息显示不含相机版本可低至 854.96 美元，促销价格具有时效性。产品支持单手、双手和多地点采集，并明确说明不能替代目标机器人上的最终高精度验证。
- **和 DexUMI / DOGlove / UMI-Dex / SynGlove 等已有方案的关系：** 属于经典 UMI 的产品化版本，动作空间仍是末端 6D+开度；与 HandUMI 相比更耐用、支持完善、相机/SLAM规范更固定，但价格更高且不穿戴在手指上；与全手外骨骼或数据手套相比无法表示多指动作；与带本体遥操作相比缺少命令—执行误差和真实机器人接触反馈。
- **对我们搭建灵巧手数据采集平台的启发：** TRumi最值得借鉴的不是机械外形，而是“原始视频不可变存档 + 分阶段可检查SLAM流水线 + MCAP/Zarr双输出 + dataset plan保存筛选结果”。我们应把每个处理阶段的成功率、丢弃原因、地图版本、标定文件和帧步长写入manifest。
- **风险或不确定性：** 依赖纹理、光照和SLAM成功率；需要mapping和ArUco标定流程；不含触觉，不能恢复真实法向/切向力或滑移；从末端中心动作映射到具体机器人仍可能遇到可达性、碰撞和动力学差异。

### VNB-Grasp

- **原始链接：** [GitHub](https://github.com/coenwerem/vnb-grasp) · [arXiv](https://arxiv.org/abs/2604.25897)
- **一句话概括：** 用可微高斯混合信念表示摩擦、接触与物体位姿的不确定性，使风险敏感抓取规划可以直接对信念参数求梯度，并提供真机和扰动 benchmark。
- **硬件是什么：** 仓库提供 ZArm 622 机械臂和 RealHand L6 的 MuJoCo 资产、YCB物体、GraspIt! force-closure抓取库；论文还包含真实多指手抓取实验。RealHand L6 为约6主动/11总自由度的轻量手。
- **采集/控制链路：**  
  `视觉/接触观测 → 潜在接触参数与物体位姿的混合信念 → 可微CVaR/抓取质量 → belief MPC → 预抓取/闭合/抬升 → 扰动与滑移评测`。
- **自由度与传感：** 重点不是人手姿态，而是每个候选接触的摩擦、位置和物体姿态不确定性；代码提供 grasp wrench space、Ferrari-Canny、软epsilon、CVaR和fragility指标。
- **反馈方式：** 执行端状态、接触不确定性和抓取稳定性；不向操作者反馈。
- **如果是 paper：** 在三种摩擦区间的仿真聚合结果中，VNB标称抓取抬升成功率79%，CEM为63%，规划速度较particle-filter MPC快约5–7倍。真机对3个物体、每方法12次，VNB达到稳定抓取所需步数和时间更少，终端抓取质量更高，并报告略低的滑移指标。
- **开源情况：** Apache-2.0；包含核心belief库、JAX可微指标、MuJoCo环境、抓取数据、控制/预抓取工具、完整配置和逐表复现说明。
- **和现有采集方案关系：** HandUMI/TRumi等负责扩展示教覆盖，VNB-Grasp负责目标机器人面对不确定摩擦和接触时如何稳健执行。两者可形成“广泛人类示教 → 目标手抓取初始化 → 风险敏感接触执行”的链路。
- **对我们搭建平台的启发：** 记录真实接触数据时不应只存单一估计值，应允许保存 `belief_type`、`contact_parameter_distribution`、`friction_regime`、`risk_level`、`perturbation_type`、`grasp_quality` 和 `slip_metric`。
- **风险或不确定性：** 仓库逐表复现主要覆盖仿真；真机传感器和驱动可能仍需厂商接口；任务偏抓取建立与抬升，不等于长程工具使用或复杂手内操作；概率信念计算比普通行为克隆部署复杂。

### HandUMI PiPER Joint-Level Samples

- **原始链接：** [handumi-screws-bipiper-joints](https://huggingface.co/datasets/Autobrik/handumi-screws-bipiper-joints) · [handumi-pick-and-place-screws-joint](https://huggingface.co/datasets/Autobrik/handumi-pick-and-place-screws-joint)
- **一句话概括：** 两个很小但字段完整的 LeRobot v3 数据样例，用于展示 HandUMI 原始双手轨迹如何转换成双 PiPER 的关节和夹爪动作。
- **硬件是什么：** 原始采集来自 HandUMI，目标机器人为双 AgileX PiPER；派生数据含左右腕相机和工作区相机。
- **采集/控制链路：** HandUMI XR/夹爪数据 → 表格工作区标定 → 双臂IK/retarget → 机器人命令序列 → LeRobot v3 Parquet/MP4。
- **自由度与传感：** 每帧14维，包括左右各6个机械臂关节和1个物理夹爪开度；视频为480×640、30Hz。较大样例3个episode、5,593帧，另一样例3个episode、1,902帧。
- **反馈方式：** 数据为命令和视频，不包含真实机器人执行误差、电流或触觉。
- **开源价值：** 元数据记录源设备、同步阈值、相机内参、工作区标定、目标机器人配置hash、TCP标定hash、retarget误差和源episode映射，适合作为数据派生manifest范例。
- **风险或不确定性：** 数据量不足以训练有泛化能力的策略；License标注为`other`且Citation未完成；`observation.state[t]`是t时刻命令、`action[t]`是t+1命令，必须避免误认为真实反馈状态。

- **复现难度：** 购买硬件后为**中**；从零复刻商业机械结构不建议。

## 6. 对我们项目的直接建议

1. **立即把HandUMI列入开源复现P0。** 先制造单只约110美元原型，跑通`doctor → record --dry-run → validate → replay`，再制作双手；无需先采购机器人。
2. **把原始采集和目标机器人派生数据彻底分层。** 原始层保存XR位姿、开度和视频；派生层保存目标URDF、TCP标定、IK配置、误差和机器人动作，避免后续换执行本体必须重新采集。
3. **建立UMI方案采购/DIY对照实验。** 对比原始UMI、HandUMI和TRumi的总成本、装配时间、设备重量、每小时有效episode、SLAM失败率、操作者疲劳和维护停机时间。
4. **MCAP应优先作为不可变原始/中间记录格式。** TRumi的MCAP保留typed消息和原始IMU，Zarr适合训练；不要只保留已经统一30Hz的数组。
5. **平行夹爪数据不能直接冒充灵巧手数据。** 数据库中增加`end_effector_class`、`finger_count`、`action_rank`和`contact_observability`，严格区分1D夹爪开度与多指动作。
6. **把不确定性和扰动加入执行端评测。** 参考VNB-Grasp，对同一抓取在不同摩擦、物体位姿误差、侧向冲击和摩擦突降条件下测试，不要只报告静态成功率。
7. **样例数据优先用于schema测试而非训练。** HandUMI当前公开样例仅3个episode，应检查时间语义、命令/执行含义和派生manifest，不应据此比较策略性能。
