# 复现路线更新｜2026-07-27

## P0：HandUMI 单手硬件与软件链

### 目标

建立可不依赖机器人本体运行的最低成本UMI基线，并验证原始机器人无关采集到目标机器人派生数据的完整版本链。

### 最小硬件

- 1套HandUMI打印件和紧固件；
- Feetech伺服/编码器；
- 鱼眼UVC相机；
- PICO 4 Ultra或Meta Quest 3与控制器；
- 计算机，Python 3.12与USB接口。

### 软件步骤

1. 克隆`robonet-ai/handumi-sw`并执行`bash install.sh`。
2. 运行`handumi doctor`和`handumi record --dry-run`。
3. 配置单相机、单控制器和单夹爪宽度源。
4. 完成相机内参、工作区和controller-to-TCP标定。
5. 记录10条抓放、插入和旋拧示教。
6. 对原始capture运行validation并保留所有失败原因。
7. 将同一批原始数据分别retarget到PiPER与OpenArm仿真。
8. 比较IK误差、碰撞、速度限制和有效episode比例。
9. 转换为LeRobot v3并检查源episode与派生episode映射。

### 必须保存

```text
source_episode_id
capture_schema
xr_device
controller_mount_version
gripper_tip_model
gripper_width_raw
gripper_width_m
camera_calibration_hash
workspace_calibration_hash
controller_tcp_calibration_hash
target_robot_config_hash
retarget_mode
retarget_position_error
retarget_rotation_error
derived_dataset_id
```

### 难度

**低到中。** 机械和软件均开放，主要风险是XR连接、USB相机、手型适配和空间标定。

## P1：HandUMI公开数据schema检查

### 数据

- https://huggingface.co/datasets/Autobrik/handumi-screws-bipiper-joints
- https://huggingface.co/datasets/Autobrik/handumi-pick-and-place-screws-joint

### 任务

1. 下载两个3-episode样例。
2. 验证`observation.state[t]`和`action[t]`的时间语义。
3. 检查双腕和工作区视频的帧数与30Hz时间轴。
4. 读取`handumi`扩展元数据中的相机、工作区、目标机器人和retarget字段。
5. 生成数据派生图：`source capture → target config → qpos → LeRobot row`。
6. 检查License=`other`，不得直接纳入可再分发训练集。

### 判定

该样例只用于schema、可视化和派生链验证，不用于策略性能结论。

## P1：VNB-Grasp快速复现

### 目标

在不购买真机的情况下，跑通概率信念、CVaR抓取指标和扰动benchmark。

### 步骤

1. 安装Python 3.10+、MuJoCo 3、PyTorch和JAX依赖。
2. 运行`examples/test_differentiable_metrics.py`。
3. 运行单次belief-MPC抓取episode。
4. 执行quick benchmark，比较VNB、Gaussian、CEM和particle-filter方法。
5. 改变摩擦区间、侧向冲击、转矩冲击和突发摩擦下降。
6. 输出抓取成功、扰动存活、规划时间、CVaR、grasp quality和slip指标。
7. 将RealHand L6替换为LEAP/MIDAS模型的可行性单独评估。

### 难度

- Quick simulation：**中**；
- 完整论文参数扫掠：**高**；
- 真机：**高**。

## P2：TRumi流程审阅

当前不建议逆向复刻商业机械结构。优先进行文档和数据流程审阅：

1. 核验mapping、gripper calibration和demo目录规范。
2. 记录ORB-SLAM3地图、IMU提取、ArUco和开度标定中间产物。
3. 对比MCAP与Zarr字段损失：MCAP保留原始IMU，Zarr偏训练回放。
4. 检查120fps视频以60fps运行SLAM时的时间轴。
5. 将其manifest设计与HandUMI和现有MCAP方案对齐。

## 复现优先级调整

| 优先级 | 项目 | 原因 |
|---|---|---|
| P0 | HandUMI单手硬件+软件 | 成本最低，硬件/软件完整开放，与无本体数据平台直接相关 |
| P1 | HandUMI样例数据 | 可快速检查LeRobot v3与retarget provenance |
| P1 | VNB-Grasp quick benchmark | 开放度高，可增加执行端不确定性和扰动评价 |
| P2 | TRumi流程审阅 | 商业硬件不适合复刻，但数据流水线值得吸收 |
