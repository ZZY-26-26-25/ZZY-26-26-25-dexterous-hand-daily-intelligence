# 分类与数据规范更新｜2026-07-27

## 1. UMI 子类型细化

在现有 `robot_free_umi` 下新增：

- `handheld_umi`：手持代理末端，例如原始UMI、TRumi。
- `wearable_gripper_umi`：戴在手指上的低维夹爪接口，例如HandUMI。
- `wearable_fullhand_umi`：记录完整或高维手指动作的穿戴设备。
- `mechanically_isomorphic_umi`：与目标机器人手在运动学/接触几何上机械同构的被动设备，例如mimic U1类路线。
- `wholebody_umi`：同时记录手、腕、头部、躯干或腿部的无本体系统。

每个系统必须记录：

```text
umi_subtype
interface_form
end_effector_class
finger_count
measured_action_rank
operator_contact_feedback
electronic_tactile_capture
pose_source
robot_in_loop
```

## 2. 低维夹爪与多指数据严格区分

新增动作空间字段：

```text
action_rank                   # 独立动作变量数量
aperture_dof                  # 夹爪开度自由度
full_finger_state_available   # 是否有完整手指状态
multi_contact_observable      # 是否能区分多个接触点
in_hand_motion_observable     # 是否能表达手内操作
```

`6D wrist + 1D aperture` 不得标记为“7DoF hand”。它是末端位姿与夹爪开度组合，不等价于具有7个可动关节的机器人手。

## 3. Robot-Agnostic Capture与Derived Robot Dataset

数据集新增两层：

### 原始采集层

```text

```

### 机器人派生层

```text
derived_dataset_id

controller_tcp_calibration_hash
retarget_method
retarget_config_hash

```

原始数据与派生数据必须保留父子关系，不得将retarget后的机器人关节数据覆盖原始人类/代理端数据。

## 4. 命令状态语义

对于LeRobot和行为克隆数据，必须显式记录：

```text
observation_state_semantics   # measured / commanded / estimated / delayed
 action_semantics             # current_command / next_command / delta / target
state_action_offset_frames
state_action_offset_seconds
execution_feedback_available
```

HandUMI PiPER样例中，`observation.state[t]`表示t时刻命令，`action[t]`表示t+1命令；这不是目标机器人的真实测量状态。

## 6. 直接物理反馈与电子触觉

将“反馈”拆分为：

- `direct_natural_feedback`：操作者直接接触物体，自然感受到力，但设备不记录力。
- `passive_mechanical_feedback`：弹簧、连杆、阻尼等产生机械手感。
- `active_haptic_feedback`：设备主动向操作者输出力或触觉。
- `electronic_tactile_capture`：设备记录压力、剪切、触点或触觉图像。
- `robot_execution_feedback`：目标机器人返回电流、effort、F/T、触觉和滑移。

上述字段可同时存在，不能用单一“有/无触觉”表示。

## 8. 开放状态细化

新增：

- `open_hardware_and_software`：制造文件与核心软件均开放，例如HandUMI。
- `commercial_hardware_open_pipeline`：硬件闭源，但处理流程/SDK开放或有公开接口，例如TRumi。
- `open_examples_proprietary_core`：公开示例依赖专有二进制SDK。
- `sample_dataset_only`：仅发布小规模格式样例，不代表完整数据集。
