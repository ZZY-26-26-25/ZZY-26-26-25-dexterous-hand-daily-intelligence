# 分类与数据规范更新｜2026-07-26

## 1. Retargeting 类型细分

### `online_kinematic_retargeting`

实时将人手骨架、指尖或骨段向量转换为机器人关节目标，强调低延迟和连续性。例如 AnyDexRetarget。

### `offline_interaction_preserving_retargeting`

离线转换完整人手—物体交互序列，强调接触语义、物体几何、碰撞和交互结构保持。例如 TopoRetarget / TopoRetarget-Repro。

### `learned_low_level_execution`

人类/retarget层只给目标，学习控制器负责机器人端接触与动力学执行。例如 TeleDexter 类方法。

三类方法的指标不能混用：实时方法关注延迟和抖动，离线方法关注交互/接触保持，低层执行方法关注真实任务成功率和接触安全。

## 3. 中间产物层

不得只保存最终机器人关节序列。推荐保留：

`raw human input`
→ `canonical human skeleton`
→ `scaled target skeleton`
→ `warm-start qpos`
→ `interaction/contact graph`
→ `optimized qpos`
→ `robot command`
→ `executed state`

对应字段：

- `canonical_skeleton_artifact`
- `scaled_skeleton_artifact`
- `warm_start_artifact`
- `interaction_graph_artifact`
- `optimization_report`
- `retargeted_action_artifact`
- `executed_state_artifact`

## 5. SDK 开放状态细分

- `open_source_sdk`：核心控制库源码可读、可修改并有明确开源License。
- `public_examples_proprietary_core`：示例代码公开，但核心库为专有二进制，例如 BrainCo RevoHand SDK。
- `commercial_documented_sdk`：提供API文档与下载，但不可公开审阅核心实现。
- `vendor_application_only`：只能通过厂商应用控制，无法编程访问。

GitHub仓库可见不能自动标记为`open_source_sdk`。

## 6. Retargeting 配置与硬件版本绑定

每条机器人数据必须绑定：

`human input device + input firmware + input calibration`
→ `retarget implementation/config`
→ `target URDF/mesh/joint mapping`
→ `target SDK/firmware`
→ `executed data`

目标手URDF或SDK升级后，旧数据不得默认与新版本等价；应通过固定回归集验证后再合并训练。
